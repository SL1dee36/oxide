# Модуль `window` — Оконная подсистема и графический контекст

Модуль `window` отвечает за инициализацию системного окна, выбор конфигурации буферов дисплея, создание аппаратного контекста OpenGL 4.5 Core Profile и управление сменяемыми буферами кадра (Double Buffering).

Исходный код: [`src/window/`](../../src/window/)

---

## 1. Стек интеграции оконной подсистемы

Для создания окна и связывания его с графическим драйвером используется связка низкоуровневых библиотек:
- **`winit 0.30`**: Создание окна операционной системы (Windows, Linux, macOS) и опрос событий оконного менеджера (изменение размеров, перерисовка, события клавиатуры и мыши).
- **`glutin 0.32` & `glutin-winit 0.5`**: Кроссплатформенная инициализация графического контекста OpenGL, выбор формата кадрового буфера (RGBA8, глубина 24 бит, трафарет 8 бит), управление вертикальной синхронизацией.
- **`raw-window-handle 0.6`**: Предоставление низкоуровневых указателей на оконные дескрипторы ОС (`HWND`, `Xlib Window`, `NSWindow`) для безопасного связывания `glutin` и `winit`.
- **`glow 0.16`**: Загрузка адресов функций OpenGL через функцию загрузчика драйвера (`gl_display.get_proc_address`) и предоставление типобезопасного Rust-интерфейса.

---

## 2. Структура `WindowContext`

`WindowContext` инкапсулирует владение графическими ресурсами уровня операционной системы:

```rust
pub struct WindowContext {
    pub window: Window,
    pub gl_context: PossiblyCurrentContext,
    pub gl_surface: Surface<WindowSurface>,
    pub glow_gl: glow::Context,
}
```

### Назначение полей:
- `window: winit::window::Window` — дескриптор системного окна.
- `gl_context: glutin::context::PossiblyCurrentContext` — активный контекст OpenGL.
- `gl_surface: glutin::surface::Surface<WindowSurface>` — поверхность кадрового буфера, привязанная к окну.
- `glow_gl: glow::Context` — таблица вызовов функций OpenGL, загруженная из видеодрайвера.

## 3. Последовательность инициализации

При вызове `WindowContext::new(title, width, height, event_loop)` выполняется следующая строгая последовательность:
1. **Конфигурация окна:** Создается `WindowAttributes` с требуемым заголовком и логическим разрешением (`winit::dpi::LogicalSize`).
2. **Выбор конфигурации буфера дисплея:** `ConfigTemplateBuilder` запрашивает 8-битный альфа-канал и обязательную аппаратную акселерацию (`prefer_hardware_accelerated(Some(true))`). Функция редукции отбирает конфигурацию с максимальным числом сэмплов сглаживания (MSAA).
3. **Запрос профиля OpenGL:** Создаются атрибуты контекста `ContextAttributesBuilder` с жестким требованием **OpenGL 4.5 Core Profile** (`ContextApi::OpenGl(Some(Version::new(4, 5)))`).
4. **Создание поверхности и активация:** Поверхность окна создается через `gl_config.create_window_surface`, после чего неактивный контекст делается текущим (`make_current(&gl_surface)`).
5. **Включение вертикальной синхронизации:** Устанавливается интервал смены буферов `SwapInterval::Wait(NonZeroU32::new(1))` для устранения разрывов кадров (screen tearing).
6. **Загрузка функций драйвера:** Вызывается `glow::Context::from_loader_function`, передающая C-строку имени каждой OpenGL функции в `gl_display.get_proc_address`.

## 4. Методы управления

### Изменение размера поверхности (`resize`)
```rust
pub fn resize(&self, width: u32, height: u32);
```
Вызывается при получении события `WindowEvent::Resized`. Если новые ширина и высота больше нуля, перенастраивает внутренние буферы `gl_surface` под новые габариты окна.

### Смена буферов кадра (`swap_buffers`)
```rust
pub fn swap_buffers(&self) -> Result<(), OxideError>;
```
Переключает передний (отображаемый на экране) и задний (в который производилась отрисовка) буферы кадра. При возникновении ошибки драйвера возвращает `OxideError::ContextError`.
